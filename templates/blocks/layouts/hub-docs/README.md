# 文档

本仓库的共享文档，由用户和所有 Agent 共同维护。它是跨会话、跨 Agent 的事实来源：任何 Agent 的私有记忆只能是这里的索引，不能替代这里。

## 目录

| 位置 | 放什么 | 怎么改 |
|---|---|---|
| `wiki/` | **现行状态**：只回答「现在是什么样」。一页一件事，150 行以内 | 状态变了就直接改成最新的样子，页首写修订日期；被推翻的决定在页尾「变更记录」留一行 |
| `insights/` | **认知**：调研、实验、教训。回答「结论是怎么来的」 | 只追加，不改写。文件名 `YYYY-MM-DD-<主题>.md`，写清来源和验证方式；后来发现有误，在原文末尾追加更正 |
| `tasks/` | 任务记录，一个任务一个文件 | 规则见 `tasks/README.md` |
| `next.md` | 调度单：先做哪个、开会话贴什么提示词 | 任何任务状态变化时同一轮更新 |
| `handoff.md` | 上一个会话留给下一个会话的话：做到哪、用户定了什么、有哪些坑、下一步 | 每次交接直接改写，只保留「现在」 |

## 页面索引

- `wiki/overview.md`：这个项目是什么、有哪些仓库、现在做到哪。**新会话先读 `handoff.md`，再读这一页。**
- `insights/`：按日期排列，打开前先看文件名。

## 写作约定

- 正文用简体中文；代码、标识符、命令、文件名用英文。
- 决定统一写成：`YYYY-MM-DD [user|self|实验] 决定内容，一句理由`。`[实验]` 表示来自已验证的实验，结果写在同一文档或链接的 `insights/` 里。
- Agent 的建议在用户确认前写成「建议（未确认）」，不能写成决定。
- 推断和事实分开写；从代码或提交记录推出来的结论标「推断」，写明依据。
- 链接用相对路径；引用的仓库路径必须存在。
- 本仓库可以记录未公开的决定；不要把这些内容抄进子仓库。

## 交接

- **开工前**：读 `handoff.md`、`wiki/overview.md`、`next.md`、要做的任务文件。
- **结束时**：改写 `handoff.md`；在任务文件里回填状态、验收、决定；现行状态变了就改 `wiki/`；新的调研、实验、教训进 `insights/`；任务状态变了就更新 `next.md`。
- **子仓库会话**只读这里，不改、不提交本仓库；回填由本仓库的会话或用户完成。
