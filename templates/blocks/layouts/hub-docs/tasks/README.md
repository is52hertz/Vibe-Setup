# 任务

一个任务一个 Markdown 文件，写目标、范围、验收和决定。

## 目录

- `hub/`：跨仓库的任务，或本仓库自己的任务。
- `<仓库>/`：属于某个子仓库的任务，目录名用子仓库的目录名。
- `<目录>/done/`：完成或作废的任务移进去保留，不删除。`done/` 是档案，不是查阅入口：长期有效的知识在归档前就要沉淀出去（见下）。

## 排序：三个字段，各管一件事

| 字段 | 管什么 | 怎么填 |
|---|---|---|
| `优先级` | **重要性**：做砸了后果多严重、可不可逆 | P0 不可逆或阻断产品；P1 影响主线；P2 该做但可缓；P3 锦上添花 |
| `截止` | **紧急性**：有没有外部时钟 | 具体日期，括号里说明有没有兜底；没有就写「无」 |
| `依赖` | **顺序**：必须先完成什么 | 任务文件路径，或「无」 |

执行顺序：先排除依赖没满足的 → 有截止且没有兜底的排最前 → 其余按优先级 → 同等条件下，耗时短又能解锁别的任务的先做。

算出来的顺序写在 `../next.md`。任务文件管「是什么」，`next.md` 管「先做哪个、怎么开工」。

## 知识归属：什么沉淀到哪里

| 知识类型 | 去哪 |
|---|---|
| 产品、仓库结构、跨仓库约定的**现行结论** | `docs/wiki/` |
| 调研、实验数据、教训 | `docs/insights/YYYY-MM-DD-<主题>.md` |
| 单个仓库的长期工程约定 | 该仓库的 `docs/<领域>.md` |
| 单个仓库的环境事实、容易踩的坑 | 该仓库的 `notice.md` |
| 只在本任务范围内成立的取舍 | 任务的「决定」小节，随任务归档 |

**沉淀是归档的前置条件**：任务移进 `done/` 之前，「沉淀」小节必须写清这轮产生的哪些知识仍然有效、分别进了哪个文件；确实没有就写「无」。

## 用法

- **派发**：子仓库的开发在工作目录为子仓库的会话或执行者里做，第一句给出任务文件路径，例如「按 `../docs/tasks/<仓库>/<任务>.md` 做」。子仓库会话只读任务文件，不改、不提交本仓库。
- **回填**：子仓库会话在结束总结里说明做了什么、逐条验收结果；由本仓库的会话或用户更新任务文件的状态、验收、决定和沉淀。
- **状态只写在任务文件里**，不另建索引。查看：`grep -H '^- 状态：\|^- 优先级：\|^- 依赖：' docs/tasks/*/*.md`
- **保持短小**：一个任务文件尽量不超过 150 行，没有内容的小节直接删掉。
- **「实现前须复核」**：标了这四个字的决定，是现在定下、但用户预期以后会改的。开工做这个功能前必须先问用户、重新论证，不能照着实现。只有用户能加上或去掉这个标记。子仓库的 `AGENTS.md` 里有同样的规则，改动时两处一起改。

## 模板

```markdown
# <任务标题>

- 状态：open | active | blocked | done | dropped
- 优先级：P0–P3
- 截止：YYYY-MM-DD（有无兜底）| 无
- 仓库：<仓库目录名>
- 依赖：<任务文件路径，或「无」>
- 创建：YYYY-MM-DD

## 目标

一两句话：做完后什么变了，为什么值得做。

## 范围

- 做：
- 不做：

## 验收

- [ ] 可检查的完成条件

## 决定

- YYYY-MM-DD [user|self|实验] 决定内容，一句理由

## 沉淀

归档前必填。

## 待定问题

-

## 参考

-
```
